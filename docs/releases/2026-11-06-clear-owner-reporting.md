# Britsmaid clear owner reporting

The approved report layout now uses expandable booking deductions, before-split expenses, owner after-split expenses and monthly TDS in calculation order. A separate Expenses section contains full expense costs, notes, evidence, allocations and change history. The chart displays the revenue allocation independently from the full expense overview, so after-split costs are not counted twice. Null and zero expense entries do not create empty categories. Other tax deductions replaces the former platform-tax wording; API field names and financial calculations remain compatible.

The existing six-month trend rendering, first-tap comparison and second-tap month navigation are unchanged. Revenue allocation segments, overview explanations, OTA breakdowns and booking details remain interactive. Admin edit links open the actual expense or source booking. Owners have no edit controls and are blocked from admin creation/edit routes; backend permissions independently reject financial writes and replacement-document uploads. Public report links remain read-only for every visitor.

Current reports refresh after an expense edit. Previously saved owner reports and payout receipts retain their amounts. Older reports without complete expense details show labelled saved summaries rather than guessing item records. Newly created payout receipts also retain the complete revenue/Britsmaid summary for future printing. No existing database records are migrated, purged or recalculated by this release.

Validation: 591 isolated backend tests, 600 statement/receipt scenarios and 2,000 deterministic app/PDF versus shared-report comparisons. Frontend typecheck, zero-warning lint, edge checks, web export and Android export passed locally. Browser checks covered owner read-only expense details and attachments, no-expense months, two-tap trend navigation, owner redirects from admin routes, admin edit from a statement, a correction refreshing both full-expense totals and owner payout, and a synthetic read-only shared report. GitHub CI additionally builds and tests the Docker deployment with disposable MongoDB. Physical Android/iPhone acceptance remains a separate device check.

All mutating browser tests use a localhost app with synthetic in-memory data and local sample media. Live verification is read-only. No paid services, storage retention, credentials, guest-ID activation or Zoho integration are changed.
